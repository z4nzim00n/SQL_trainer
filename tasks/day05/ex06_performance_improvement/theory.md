# Задание 06. Подбор покрывающего индекса

Чтобы понять, какой индекс поможет, разбери запрос на части и посмотри, к каким столбцам он обращается:

- соединение `menu` и `pizzeria`: по `menu.pizzeria_id = pizzeria.id`;
- оконная функция берёт `rating` из `pizzeria`;
- из `menu` нужно только `pizza_name`.

Покрывающий индекс содержит **все** столбцы таблицы, нужные запросу, тогда PostgreSQL читает только индекс (`Index Only Scan`). Для таблицы `pizzeria` это `id` (ключ соединения) и `rating`.

Сравнивать варианты помогает `EXPLAIN ANALYZE`: смотри на строки `Index ... Scan using idx_1` и на `cost` в первой строке плана (чем ниже, тем лучше, по оценке планировщика) и на `Execution Time`.

Метод подбора: создал индекс, посмотрел план, удалил (`DROP INDEX idx_1`), создал другой. Так находится индекс, который реально включается в план.

Ключевые слова для примеров: `CREATE INDEX`, `EXPLAIN ANALYZE`, `PARTITION BY`, `OVER`, `DROP`.
