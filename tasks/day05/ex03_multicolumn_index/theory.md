# Задание 03. Составной и покрывающий индекс

Индекс можно построить по нескольким столбцам сразу: `CREATE INDEX имя ON таблица (a, b, c)`. Он хранит пары/тройки значений, отсортированные по `a`, затем по `b`, затем по `c`.

Два правила:

1. **Порядок столбцов важен.** Индекс быстро работает по условиям на **левую часть** набора: `a`, или `a и b`. Условие только на `b` его почти не использует.
2. **Покрывающий индекс.** Если в индексе есть **все** столбцы, нужные запросу (и в `SELECT`, и в `WHERE`), PostgreSQL берёт данные прямо из индекса, не обращаясь к таблице. В плане это `Index Only Scan`.

В нашем запросе в условии `person_id` и `menu_id`, а в `SELECT` ещё `order_date`. Значит, в индекс нужно положить все три столбца.

Аналог: `CREATE INDEX ... ON person_order (person_id, menu_id) INCLUDE (order_date)`: дополнительный столбец лежит в индексе, но не участвует в сортировке.

Ключевые слова для примеров: `CREATE INDEX`, `INDEX`, `EXPLAIN`.
