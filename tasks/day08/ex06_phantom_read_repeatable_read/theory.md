# Задание 06. REPEATABLE READ и фантомы

Стандарт SQL допускает фантомы на `REPEATABLE READ`. Но в PostgreSQL этот уровень реализован через **снимок**: транзакция видит базу ровно такой, какой она была в момент первого запроса, поэтому новые чужие строки ей не видны. Фантомов здесь нет.

Это отличие PostgreSQL от некоторых других СУБД (например, MySQL/InnoDB ведёт себя иначе в части блокировок). Поэтому ответы на вопрос «защищает ли REPEATABLE READ от фантомов?» зависят от СУБД.

Сводная таблица для PostgreSQL:

| Уровень изоляции | Грязное чтение | Неповторяющееся чтение | Фантомное чтение |
| --- | --- | --- | --- |
| `READ UNCOMMITTED` (в PostgreSQL работает как `READ COMMITTED`) | нет | возможно | возможно |
| `READ COMMITTED` (по умолчанию) | нет | возможно | возможно |
| `REPEATABLE READ` | нет | нет | нет в PostgreSQL (по стандарту возможно) |
| `SERIALIZABLE` | нет | нет | нет |

Ключевые слова для примеров: `BEGIN`, `COMMIT`, `INSERT`, `SUM`, `TRANSACTION`.
