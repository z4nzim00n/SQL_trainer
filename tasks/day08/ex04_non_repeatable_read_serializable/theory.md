# Задание 04. SERIALIZABLE: транзакции как будто идут по очереди

`SERIALIZABLE` самый строгий уровень: результат параллельных транзакций такой, будто они выполнялись **одна за другой**.

В этом задании видно главное свойство снимка: Session #1 после `BEGIN` и первого чтения «замораживает» картину мира. Чужие `COMMIT` она не видит, пока сама не закончит транзакцию. Поэтому повторное чтение вернёт то же самое (в отличие от `READ COMMITTED` из задания 03).

Цена строгости: иногда PostgreSQL прерывает транзакцию с ошибкой `could not serialize access due to read/write dependencies among transactions`. Приложение обязано быть готово **повторить** транзакцию. В нашем сценарии Session #1 только читает, поэтому ошибки не будет.

Ключевые слова для примеров: `BEGIN`, `COMMIT`, `TRANSACTION`.
