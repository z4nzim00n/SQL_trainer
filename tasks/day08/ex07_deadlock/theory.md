# Задание 07. Deadlock

**Взаимная блокировка** (deadlock) возникает, когда транзакции ждут друг друга по кругу:

1. Session #1 блокирует строку A;
2. Session #2 блокирует строку B;
3. Session #1 хочет строку B и ждёт Session #2;
4. Session #2 хочет строку A и ждёт Session #1.

Никто не может продолжить. PostgreSQL сам находит такой цикл (проверка запускается после `deadlock_timeout`, по умолчанию 1 секунда) и **убивает одну из транзакций** с ошибкой `deadlock detected`. Остальные продолжают.

Как защищаются:

- блокировать строки **всегда в одном порядке** (например, по возрастанию `id`);
- делать транзакции короткими;
- уметь повторять транзакцию после такой ошибки.

В задании строки блокируются в разном порядке: Session #1 берёт 1, потом 2, а Session #2 берёт 2, потом 1. Именно это и даёт крест.

Ключевые слова для примеров: `BEGIN`, `ROLLBACK`, `UPDATE`, `TRANSACTION`.
