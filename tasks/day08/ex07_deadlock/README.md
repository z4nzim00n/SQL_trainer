# Задание 07. Взаимная блокировка (Deadlock)

**Язык:** SQL

Воспроизведи **взаимоблокировку**: две транзакции захватили по одной строке и теперь каждая ждёт строку, которую держит другая, «крест-накрест». Любой уровень изоляции (по умолчанию подойдёт). Работай с таблицей `pizzeria`.

Выполни шаги строго в этом порядке:

| Шаг | Session #1 | Session #2 |
| --- | --- | --- |
| 1 | `BEGIN;` | `BEGIN;` |
| 2 | `UPDATE pizzeria SET rating = 5 WHERE id = 1;` |  |
| 3 |  | `UPDATE pizzeria SET rating = 5 WHERE id = 2;` |
| 4 | `UPDATE pizzeria SET rating = 5 WHERE id = 2;` |  |
| 5 |  | `UPDATE pizzeria SET rating = 5 WHERE id = 1;` |
| 6 | `ROLLBACK;` | `ROLLBACK;` |

**Что должно получиться.**

- шаг 4 (Session #1): команда **зависает**: строка 2 занята Session #2;
- шаг 5 (Session #2): после паузы около секунды PostgreSQL обнаруживает цикл ожидания и прерывает одну из транзакций:

```
ERROR:  deadlock detected
DETAIL:  Process ... waits for ShareLock on transaction ...; blocked by process ...
```

- вторая транзакция после этого может продолжить; обе в конце завершай `ROLLBACK`.

> **Подготовка.** Открой **два** терминала (или две консоли в DataGrip) и в каждом подключись к своей базе: `psql -d pizza_db`. Это Session #1 и Session #2. Перед заданием верни рейтинг в исходное состояние: `UPDATE pizzeria SET rating = 4.6 WHERE name = 'Pizza Hut';`.
> Тренажёр работает с одним подключением и не умеет две параллельные сессии, поэтому автопроверки здесь нет: ты делаешь задание в psql, сверяешься с ожидаемым результатом и нажимаешь «Отметить как выполненное».
