# Задание 03. Неповторяющееся чтение (READ COMMITTED)

**Язык:** SQL

**Неповторяющееся чтение**: в рамках одной транзакции один и тот же запрос возвращает разные значения, потому что между запросами другая транзакция успела изменить данные и зафиксировать их.

Проверь это на уровне `READ COMMITTED`. В Session #1 прочитай рейтинг `Pizza Hut` в транзакции, затем в Session #2 обнови его до `3.6` и зафиксируй, потом снова прочитай в Session #1.

Выполни шаги строго в этом порядке:

| Шаг | Session #1 | Session #2 |
| --- | --- | --- |
| 1 | `BEGIN;` | `BEGIN;` |
| 2 | `SELECT rating FROM pizzeria WHERE name = 'Pizza Hut';` |  |
| 3 |  | `UPDATE pizzeria SET rating = 3.6 WHERE name = 'Pizza Hut';` |
| 4 |  | `COMMIT;` |
| 5 | `SELECT rating FROM pizzeria WHERE name = 'Pizza Hut';` |  |
| 6 | `COMMIT;` |  |
| 7 | `SELECT rating FROM pizzeria WHERE name = 'Pizza Hut';` |  |

**Что должно получиться.**

- шаг 2 (Session #1): старое значение, например `4.6`;
- шаг 5 (Session #1): **уже `3.6`**, хотя транзакция Session #1 всё ещё открыта: один и тот же запрос в одной транзакции дал два разных ответа.

> **Подготовка.** Открой **два** терминала (или две консоли в DataGrip) и в каждом подключись к своей базе: `psql -d pizza_db`. Это Session #1 и Session #2. Перед заданием верни рейтинг в исходное состояние: `UPDATE pizzeria SET rating = 4.6 WHERE name = 'Pizza Hut';`.
> Тренажёр работает с одним подключением и не умеет две параллельные сессии, поэтому автопроверки здесь нет: ты делаешь задание в psql, сверяешься с ожидаемым результатом и нажимаешь «Отметить как выполненное».
