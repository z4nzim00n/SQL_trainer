## Идея

Session #1 дважды читает одну и ту же строку в одной транзакции, а между чтениями Session #2 меняет и фиксирует рейтинг.

## Каркас

```sql
-- Session #1: BEGIN; SELECT rating ...;   (старое значение)
-- Session #2: BEGIN; UPDATE ... SET rating = ______; ______;
-- Session #1: SELECT rating ...;           (новое значение!)
--             COMMIT;
```

## Почти ответ

Если во втором чтении в Session #1 всё ещё старое значение, значит, в Session #2 не сделан `COMMIT`. Рейтинг должен стать `3.6` до повторного чтения.
