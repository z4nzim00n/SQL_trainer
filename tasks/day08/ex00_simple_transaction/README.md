# Задание 00. Простая транзакция

**Язык:** SQL

Нужно проверить, **когда** изменения, сделанные в одной сессии, становятся видны другим. Для этого понадобятся два параллельных сеанса `psql`.

Докажи, что параллельная сессия **не видит** изменения, пока ты не сделал `COMMIT`, и видит их сразу после.

- **Session #1:** обнови рейтинг `Pizza Hut` до 5 в режиме транзакции и убедись, что ты сам видишь изменение.
- **Session #2:** убедись, что изменения **не видны**.
- **Session #1:** сделай `COMMIT`.
- **Session #2:** убедись, что изменения **теперь видны**.

Выполни шаги строго в этом порядке:

| Шаг | Session #1 | Session #2 |
| --- | --- | --- |
| 1 | `BEGIN;` |  |
| 2 | `UPDATE pizzeria SET rating = 5 WHERE name = 'Pizza Hut';` |  |
| 3 | `SELECT * FROM pizzeria WHERE name = 'Pizza Hut';` |  |
| 4 |  | `SELECT * FROM pizzeria WHERE name = 'Pizza Hut';` |
| 5 | `COMMIT;` |  |
| 6 |  | `SELECT * FROM pizzeria WHERE name = 'Pizza Hut';` |

**Что должно получиться.**

- шаг 3 (Session #1): рейтинг `5`: транзакция видит свои собственные изменения;
- шаг 4 (Session #2): рейтинг `4.6`: чужая незафиксированная правка не видна;
- шаг 6 (Session #2): рейтинг `5`: после `COMMIT` правка видна всем.

Один и тот же запрос в Session #2 возвращает разные результаты: до и после фиксации в Session #1.

> **Подготовка.** Открой **два** терминала (или две консоли в DataGrip) и в каждом подключись к своей базе: `psql -d pizza_db`. Это Session #1 и Session #2. Перед заданием верни рейтинг в исходное состояние: `UPDATE pizzeria SET rating = 4.6 WHERE name = 'Pizza Hut';`.
> Тренажёр работает с одним подключением и не умеет две параллельные сессии, поэтому автопроверки здесь нет: ты делаешь задание в psql, сверяешься с ожидаемым результатом и нажимаешь «Отметить как выполненное».
