# Задание 01. Lost Update на READ COMMITTED

На уровне `READ COMMITTED` каждая команда видит данные, зафиксированные **к моменту её начала**.

Что происходит по шагам:

1. обе сессии читают рейтинг (например, 4.6);
2. Session #1 меняет строку, на неё ставится блокировка;
3. `UPDATE` в Session #2 упирается в блокировку и **ждёт**;
4. Session #1 делает `COMMIT`, блокировка снята;
5. Session #2 повторно читает актуальную версию строки и применяет свой `UPDATE`: `rating = 3.6` безусловно перезаписывает `4`.

Итог: одно из обновлений пропало. База не нарушила правил: каждая команда по отдельности корректна. Проблема в приложении: оно записало значение, вычисленное по **устаревшему** чтению.

Защита: обновлять относительно текущего значения (`SET rating = rating + 1`), блокировать строку при чтении (`SELECT ... FOR UPDATE`), либо использовать более строгий уровень изоляции (следующее задание).

Ключевые слова для примеров: `BEGIN`, `COMMIT`, `UPDATE`, `TRANSACTION`.
