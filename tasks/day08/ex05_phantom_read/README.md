# Задание 05. Фантомное чтение (READ COMMITTED)

**Язык:** SQL

**Фантомное чтение**: в одной транзакции один и тот же запрос по условию возвращает разный **набор строк**, потому что другая транзакция добавила (или удалила) подходящие строки и зафиксировалась.

В Session #1 просумми рейтинги всех пиццерий в транзакции, затем в Session #2 добавь новую пиццерию `'Kazan Pizza'` с рейтингом `5` и `id = 10`, зафиксируй и снова просумми в Session #1.

Выполни шаги строго в этом порядке:

| Шаг | Session #1 | Session #2 |
| --- | --- | --- |
| 1 | `BEGIN;` | `BEGIN;` |
| 2 | `SELECT SUM(rating) FROM pizzeria;` |  |
| 3 |  | `INSERT INTO pizzeria (id, name, rating) VALUES (10, 'Kazan Pizza', 5);` |
| 4 |  | `COMMIT;` |
| 5 | `SELECT SUM(rating) FROM pizzeria;` |  |
| 6 | `COMMIT;` |  |
| 7 | `SELECT SUM(rating) FROM pizzeria;` |  |

**Что должно получиться.**

- шаг 2 (Session #1): сумма всех рейтингов, например `S`;
- шаг 5 (Session #1): сумма **`S + 5`**: в выборку попала новая строка, которой не было при первом чтении;
- шаг 7: то же `S + 5`.

> **Подготовка.** Открой **два** терминала (или две консоли в DataGrip) и в каждом подключись к своей базе: `psql -d pizza_db`. Это Session #1 и Session #2. Перед заданием верни рейтинг в исходное состояние: `UPDATE pizzeria SET rating = 4.6 WHERE name = 'Pizza Hut';`.
> Тренажёр работает с одним подключением и не умеет две параллельные сессии, поэтому автопроверки здесь нет: ты делаешь задание в psql, сверяешься с ожидаемым результатом и нажимаешь «Отметить как выполненное».
