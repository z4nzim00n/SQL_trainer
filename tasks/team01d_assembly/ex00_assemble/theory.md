# Теория: представления поверх сложных запросов

Представление (`VIEW`) — это сохранённый запрос с именем. Оно позволяет использовать результат сложного запроса, как таблицу:

```sql
CREATE VIEW v_total_volume AS
SELECT ... ;      -- без ORDER BY
```

Сортировку лучше оставлять внешнему запросу.

## Как собрать

1. `INSERT` для данных.
2. `CREATE VIEW` Роли 1 (названия столбцов `name`, `lastname`, `currency_name`, `total_volume_in_usd`).
3. `CREATE VIEW` Роли 2 (названия столбцов `name`, `lastname`, `currency_name`, `currency_in_usd`).
4. Итоговый `SELECT`.

## Сверка двух представлений

Строки представлений разной «зернистости»: в первом одна строка на пользователя, тип и валюту, во втором одна строка на операцию. Чтобы их сравнить, приведите оба к общему виду: сумма по `name`, `lastname`, `currency_name`. Потом `JOIN` по этим трём столбцам.

Если у пользователя есть оба представления, но суммы расходятся: это нормально, ведь курсы менялись. Разность `diff` показывает, сколько «выиграл» или «потерял» пользователь из-за изменения курса.

Ключевые слова для примеров: `CREATE VIEW`, `GROUP BY`, `JOIN`, `SUM`.
