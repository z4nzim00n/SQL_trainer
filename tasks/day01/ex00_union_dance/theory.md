# Задание 00. UNION

Оператор `UNION` ставит результаты двух запросов друг под другом, как две таблицы, сложенные стопкой. Чтобы это сработало, в обоих запросах должно быть одинаковое число столбцов, а типы на одних и тех же местах должны совпадать: число с числом, текст с текстом. Здесь подходят пары «номер и название»: у `menu` это `id` и `pizza_name`, у `person` это `id` и `name`.

Названия столбцов итоговой таблицы берутся из первого запроса, поэтому переименовывать нужно именно там, через `AS`: `SELECT id AS object_id`. Во втором запросе названия повторять не нужно.

`ORDER BY` пишется один раз в самом конце, после последнего запроса, и сортирует весь объединённый результат. Сортировать можно по нескольким столбцам через запятую: сначала по первому, а при равных значениях по второму. В `ORDER BY` используются уже новые имена из первого запроса.

Обычный `UNION` ещё и убирает полностью одинаковые строки, а `UNION ALL` их оставляет. В этом задании полных дублей нет, поэтому подойдёт любой из двух.

## Примеры на маленьких таблицах

Две крошечные таблицы `a` и `b`. `UNION` складывает их друг под другом и убирает повторы:

```sql-run
SELECT id, val FROM a
UNION
SELECT id, val FROM b
ORDER BY id, val;
```

`AS` даёт столбцу новое имя в результате, названия берутся из первого запроса:

```sql-run
SELECT id AS object_id, val AS object_name FROM a
UNION
SELECT id, val FROM b
ORDER BY object_id, object_name;
```
