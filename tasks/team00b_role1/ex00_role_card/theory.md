# Теория Роли 1: данные и итоговые выборки

## Таблица рёбер

Граф описывается таблицей из трёх столбцов:

```sql
CREATE TABLE nodes (
    point1 varchar NOT NULL,   -- откуда
    point2 varchar NOT NULL,   -- куда
    cost   integer NOT NULL    -- стоимость перехода
);
```

Рёбра у нас двусторонние. Чтобы запросы были простыми, в таблицу вносим **две строки** на каждое ребро: `(a, b, 10)` и `(b, a, 10)`. Для 4 городов это 6 рёбер × 2 = **12 строк**.

Вставить много строк можно одним `INSERT`:

```sql
INSERT INTO nodes (point1, point2, cost) VALUES
    ('a', 'b', 10), ('b', 'a', 10),
    ('a', 'c', 15), ('c', 'a', 15);
```

## Выбор «минимум по всем»

Нужны строки, у которых значение равно минимуму. Приём: подзапрос с агрегатом.

```sql
SELECT * FROM v_all_tours
WHERE total_cost = (SELECT MIN(total_cost) FROM v_all_tours);
```

Так возвращаются **все** маршруты с минимальной стоимостью, а не один (в отличие от `ORDER BY ... LIMIT 1`). Если лучших несколько, нужны все.

## Универсальность

Хороший запрос не знает, сколько городов в графе. Проверь: добавь пятый город и убедись, что итог пересчитывается сам. Это и есть задание ex03.

Ключевые слова для примеров: `INSERT`, `MIN`, `ORDER BY`, `VIEW`.
