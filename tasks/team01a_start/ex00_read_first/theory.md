# Теория: что общего у обеих ролей

## Что такое ODS

ODS (Operational Data Store) хранит данные почти так, как они пришли из систем-источников. Здесь их ещё не «чистят»: все дефекты источников видны. Поэтому первое, что делает аналитик: выясняет, какие аномалии есть, и пишет запросы, которые их переживают.

## Временная таблица

Если таблица хранит только текущее состояние (как в OLTP), старые значения теряются. В хранилище нужна история: добавляют столбец с отметкой времени (`updated`), и каждое изменение превращается в **новую строку**. Чтобы узнать значение на нужный момент, надо выбрать строку по времени:

- **последнее** значение: строка с максимальным `updated`;
- значение **на момент T**: строка с максимальным `updated`, не позже T.

## Связи без внешних ключей

Между таблицами нет `FOREIGN KEY`, поэтому нельзя быть уверенным, что `balance.user_id` есть в `"user"`. Для таких связей используют `LEFT JOIN`: он оставляет строки левой таблицы, даже если пары нет. Недостающие значения станут `NULL`, а `COALESCE` заменит их на запасные.

```sql
SELECT COALESCE(u.name, 'not defined') AS name
FROM balance b
LEFT JOIN "user" u ON u.id = b.user_id;
```

Ключевые слова для примеров: `LEFT JOIN`, `COALESCE`, `NULL`, `VIEW`, `GROUP BY`.
