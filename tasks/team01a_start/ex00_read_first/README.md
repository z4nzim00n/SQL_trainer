# Командный проект: хранилище данных (DWH)

Проект выполняют **двое**. Выберите роли и найдите их в левом списке:

- **Роль 1 · «Аналитик хранилища»**: учитывает все операции по балансу и считает итоговый объём в долларах по **последнему** курсу валюты. Раздел «Team 01 · Роль 1».
- **Роль 2 · «Инженер курсов»**: для каждой операции находит курс, который действовал **на момент операции**. Раздел «Team 01 · Роль 2».

Когда обе части готовы, сделайте **общую сборку**: раздел «Team 01 · Общая сборка».

## Идея проекта

Хранилище данных (DWH) собирает данные из разных систем, чтобы по ним можно было строить отчёты. Два классика предлагали разные способы его строить: Билл Инмон («предметно-ориентированная, интегрированная, неизменяемая и изменяемая во времени коллекция данных для принятия решений») и Ральф Кимбал (данные очищаются и загружаются в хранилище измерений). Сегодня к ним добавился LakeHouse: смесь DataLake и DataWareHouse.

В этом проекте вы работаете с первым слоем хранилища: **ODS** (Operational Data Store). Это копия данных из источников со всеми их недостатками.

## Источники данных

Три независимых системы (в духе микросервисов):

- **Green**: пользователи.
- **Red**: валюты и курсы.
- **Blue**: операции по балансу.

В хранилище лежат три таблицы:

| Таблица | Столбцы | Комментарий |
| --- | --- | --- |
| `"user"` | `id`, `name`, `lastname` | имя и фамилия могут быть `NULL` |
| `currency` | `id`, `name`, `rate_to_usd`, `updated` | `id` повторяется: строка на каждое изменение курса |
| `balance` | `user_id`, `money`, `type`, `currency_id`, `updated` | внешних ключей нет |

`currency` хранит **историю**: каждый раз, когда курс менялся, добавлялась новая строка с отметкой `updated`. Так таблица становится *временной* (temporal): `id` в ней уже не уникален.

Пример для `EUR`:

| id | name | rate_to_usd | updated |
| --- | --- | --- | --- |
| 100 | EUR | 0.9 | 2022-03-03 13:31 |
| 100 | EUR | 0.89 | 2022-03-02 12:31 |
| 100 | EUR | 0.87 | 2022-03-02 08:00 |
| 100 | EUR | 0.9 | 2022-03-01 15:36 |

## Аномалии данных

Источники независимы, поэтому данные несогласованы:

- в `balance` есть пользователь, которого нет в `"user"` (и наоборот: пользователь без единой операции);
- в `balance` есть валюта, которой нет в `currency`;
- в `"user"` бывают `NULL` в `name` и `lastname`.

Строки-«сироты» удалять нельзя: деньги были, значит, их надо учесть. Поэтому в запросах нужны `LEFT JOIN` и `COALESCE`.

## Договорённость между ролями

| Что | Имя | Кто создаёт |
| --- | --- | --- |
| итоговые объёмы по пользователям (задание 00 проекта) | `v_total_volume` | Роль 1 |
| операции в долларах по курсу на момент операции (задание 01 проекта) | `v_balance_usd` | Роль 2 |

Именно эти два представления вы соедините в общей сборке.

## Про таблицу `"user"`

Слово `user` в PostgreSQL зарезервировано, поэтому таблицу пишут в **двойных кавычках**: `"user"`. Без кавычек запрос вернёт не таблицу, а имя текущего пользователя.
