# 10. psql, ошибки и приёмы

## Команды psql

Команды psql начинаются с обратного слэша и **не** заканчиваются точкой с запятой. Это команды клиента, а не SQL.

| Команда | Что делает |
| --- | --- |
| `\dt` | список таблиц |
| `\d имя_таблицы` | столбцы, типы и ключи таблицы |
| `\l` | список баз |
| `\c имя_базы` | переключиться на другую базу |
| `\i путь/к/файлу.sql` | выполнить файл со скриптом |
| `\x` | вертикальный вывод (удобно для широких таблиц) |
| `\timing` | показывать время выполнения |
| `\q` | выйти |

SQL-запрос в psql заканчивается точкой с запятой. Если её не поставить, psql будет ждать продолжения (приглашение меняется на `-#`): допиши `;` и нажми Enter.

## Расшифровка ошибок

| Сообщение | Причина и что делать |
| --- | --- |
| `syntax error at or near "..."` | опечатка или лишняя запятая; смотри слово из ошибки и строку перед ним |
| `column "x" does not exist` | неверное имя столбца или текст в двойных кавычках вместо одинарных |
| `relation "x" does not exist` | нет такой таблицы или подключён не к той базе / схеме |
| `column reference "id" is ambiguous` | столбец есть в двух таблицах: добавь префикс (`person.id`) |
| `each UNION query must have the same number of columns` | в частях `UNION` разное число столбцов |
| `UNION types integer and text cannot be matched` | на одном месте число и текст: приведи через `CAST` |
| `column "x" must appear in the GROUP BY clause or be used in an aggregate function` | столбец в `SELECT` не из `GROUP BY` и не в агрегате |
| `aggregate functions are not allowed in WHERE` | условие по агрегату пиши в `HAVING` |
| `subquery in FROM must have an alias` | подзапросу в `FROM` нужен псевдоним |
| `more than one row returned by a subquery used as an expression` | скалярный подзапрос вернул несколько строк |
| `invalid input syntax for type ...` | значение не подходит под тип (например, текст вместо числа) |
| `division by zero` | делишь на 0: используй `NULLIF(x, 0)` |
| `duplicate key value violates unique constraint` | вставляешь значение, которое уже есть в уникальном столбце |

## Как писать запросы без боли

1. **Начни с `FROM`.** Реши, какие таблицы нужны и как они связаны.
2. Добавь `JOIN` и сразу проверь запрос с `SELECT *` и `LIMIT 10`.
3. Добавляй `WHERE`, потом `GROUP BY` / `HAVING`, потом нужные столбцы и `ORDER BY`.
4. Проверяй результат на глаз: число строк, `NULL`, дубликаты.
5. Подозрительно много строк: скорее всего, размножились строки из-за `JOIN`.
6. Подозрительно мало строк: смотри `INNER JOIN` вместо `LEFT`, `NULL` в условиях, `NOT IN`.

## Формат и стиль

- Ключевые слова пиши заглавными (`SELECT`, `FROM`), имена маленькими.
- Каждое предложение (`FROM`, `WHERE`, `JOIN`) с новой строки.
- Всегда пиши `ORDER BY`, если порядок важен.
- Перечисляй столбцы вместо `*` в готовых запросах.
- Длинные запросы разбивай на `WITH`.

## Быстрые приёмы

```sql
-- число строк в таблице
SELECT COUNT(*) FROM person;

-- есть ли дубликаты по столбцу
SELECT pizza_name, COUNT(*) FROM menu GROUP BY pizza_name HAVING COUNT(*) > 1;

-- посмотреть план выполнения
EXPLAIN SELECT * FROM menu WHERE price > 800;
```
