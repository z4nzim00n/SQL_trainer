# Как добавлять задания (для человека или любой нейросети)

Страница `index.html` и код в `js/` и `css/` менять **не нужно**. Всё содержимое тренажёра лежит в `tasks/` и `data/`, а `tasks.json` собирается из них командой `node tools/build.mjs`.

## Что менять

| Хочу | Что делать |
|---|---|
| Новое задание | папка `tasks/dayNN/exNN_название/` с 6 файлами (ниже) |
| Новый день | папка `tasks/dayNN/` с `day.json` вида `{"title": "Day 02. ..."}` |
| Новую модель БД | файлы `data/<имя>.sql`, по желанию `data/<имя>_alt.sql` и `data/<имя>_schema.md`; в `meta.json` задания `"dataset": "<имя>"` |
| Слово для кликабельного словаря | `docs/glossary*.json` (см. ниже) |
| Статью справочника | файл `docs/NN_название.md` (первая строка `# Заголовок`) |
| Изменить вид страницы | `css/app.css`, `index.html`, `js/app.js` |

После любых изменений в `tasks/` или `data/`: `node tools/build.mjs`, затем закоммитить `tasks.json`.

## Файлы задания

- `README.md` — условие (Markdown).
- `theory.md` — короткая теория, без готового решения.
- `hints.md` — три подсказки по нарастающей; каждая начинается с `## Заголовок`.
- `solution.sql` — эталон. Именно с ним сравниваются ответы.
- `solution_commented.sql` — тот же запрос с построчными комментариями.
- `meta.json`:
  - `title`, `dataset` (имя из `data/`), `ordered` (важен ли порядок строк);
  - `forbidden` / `required` — слова, которые запрещены / обязательны (`["DISTINCT"]`);
  - `positive` — другие верные решения: `[{"why": "...", "sql": "..."}]`, они обязаны проходить;
  - `negative` — типичные ошибки: `[{"why": "...", "sql": "..."}]`, они обязаны отклоняться;
  - необязательно `"checkColumns": false`, если имена столбцов не важны;
  - необязательно `"orderKeys": ["столбец"]`: порядок строк проверяется только по этим столбцам (нужно, если при равных значениях сортировки порядок строк не задан условием).

## Примеры с кнопкой «Показать пример»

В `theory.md`, `README.md` и статьях `docs/` блок кода с языком `sql-run` получает кнопку: запрос выполняется на настоящей базе и показывает результат. Обычный блок ```sql остаётся просто текстом. В любом `.md` строка `{{venn:inner}}` превращается в диаграмму Венна (виды: `inner`, `left`, `left_only`, `right`, `right_only`, `full`, `full_only`, `a_only`). Каждый `sql-run` проверяет `tools/validate.mjs`.

## Задания на изменение базы (INSERT, UPDATE, VIEW, индексы, функции, триггеры)

Запрос ученика выполняется в транзакции, которая откатывается, поэтому проверяется не результат самой команды, а состояние базы после неё. Для этого в `meta.json` добавляются поля:

- `"setup"`: SQL, который выполняется **до** решения (например, результат предыдущих заданий: создать нужное представление или добавить пиццу). Выполняется и для ученика, и для эталона.
- `"verify"`: SELECT, который выполняется **после** решения. Сравниваются именно его результат (названия столбцов и строки) у ученика и у эталона. Для схемы текущей базы пользуйся `current_schema()` (`information_schema`, `pg_indexes` и т. п. фильтруй по `schemaname = current_schema()` / `table_schema = current_schema()`).

Если у задания есть `verify`, то ученик может писать любую команду, а не только SELECT. Запрещённые слова проверяются только в тексте решения ученика.

## Какие примеры где

- ```` ```sql-run ```` в теории и справочнике выполняется на учебных мини-таблицах (`data/demo.sql`: `a`, `b`, `courses`, `students`, `products`, `sales`), которые **показываются над примером**. Не про пиццерии.
- ```` ```sql-pizza ```` выполняется на базе пиццерий (когда нужен именно её вид).
- В `docs/glossary.json` лежит словарь терминов: ключ в верхнем регистре, значения `title`, `text`, `sql`. Любое слово из словаря в обратных кавычках (`` `UNION` ``) в тексте становится кликабельным и открывает окно с примером.

## Скрытые данные

`data/<имя>_alt_<что-угодно>.sql` тоже дописываются к скрытому набору (после `<имя>_alt.sql`, по алфавиту). Все идентификаторы в скрытых строках берись **от 100 и выше**: задания про INSERT используют небольшие ids.

`data/<имя>_alt.sql` дописывается поверх основного скрипта и создаёт второй набор. Проверка идёт на обоих, поэтому ответ нельзя «захардкодить». Добавляй туда строки, на которых ломаются типичные неверные решения (дубликаты, NULL, регистр букв, лишние связи).

## Проверка перед коммитом

```
createdb trainer_test
PGDATABASE=trainer_test node tools/validate.mjs --verbose
```

Эталон и все `positive` должны проходить, все `negative` — отклоняться. Дополнительно открой в браузере `/?selftest`.

## Промпт для нейросети

## Ручные задания (два окна psql, транзакции)

Если задание нельзя проверить в браузере (например, две параллельные сессии), в `meta.json` ставится `"manual": true`. Тогда кнопки проверки нет: страница показывает «Ручное задание» и кнопку «Отметить как выполненное». Файлы задания всё равно нужны (README, theory, hints, solution.sql с шагами для Session #1 и Session #2, solution_commented.sql); `meta.json` может содержать только `title`, `dataset`, `manual`.
