# SQL Practice (v0.004)

Тренажёр по SQL для подготовки к экзамену. Запросы выполняются прямо в браузере на настоящем PostgreSQL (PGlite, WebAssembly): ничего ставить не нужно.

В версии 0.001 три задания Day 01 (ex00, ex01, ex02). У каждого есть условие, схема базы, теория, три подсказки по нарастающей, эталонное решение с комментариями и автопроверка.

## Запуск на своём компьютере

```
cd sql-trainer
python3 -m http.server 8000
```

Открой http://localhost:8000. Двойным кликом по `index.html` страница не заработает: браузер не даёт читать `tasks.json` и грузить WebAssembly с `file://`.

Нужен интернет: PGlite подгружается с CDN (jsDelivr, запасной источник esm.sh), шрифты с Google Fonts. Первый запуск скачивает несколько МБ, дальше браузер берёт их из кэша.

Справа внизу две вкладки: «Вывод» и «Схема БД» (граф таблиц с PK/FK и содержимое любой таблицы по клику).

В левом меню кнопка «📖 Энциклопедия SQL»: 10 статей с живыми примерами и диаграммами JOIN, есть поиск. В теории заданий тоже есть кнопки «Показать пример».

Как добавлять задания и подключать другую нейросеть: см. `AUTHORING.md`.

## Проверка, что движок работает

Открой http://localhost:8000/?selftest. Страница прогонит в браузере все эталоны и все «неверные» решения. В заголовке вкладки появится `SELFTEST OK` и список галочек. Если вместо этого `SELFTEST FAIL`, открой консоль браузера (F12) и пришли текст ошибки.

## Выкладка на GitHub Pages

1. Залей папку проекта в репозиторий (вместе с `tasks.json`).
2. Settings → Pages → Build and deployment → Deploy from a branch → `main`, папка `/ (root)`.
3. Через минуту страница будет по адресу `https://<ник>.github.io/<репозиторий>/`.

## Как проверяется решение

Запрос ученика и эталонное решение выполняются на двух наборах данных: основном (`data/pizza.sql`) и скрытом (`data/pizza_alt.sql` добавляет строки поверх основного). Сравниваются названия столбцов, строки (с учётом дубликатов) и порядок строк, если в `meta.json` стоит `"ordered": true`. Благодаря скрытому набору нельзя пройти задание, вписав готовый ответ через `VALUES`. Запреты из условия (`DISTINCT`, `JOIN` и т. п.) проверяются по тексту запроса без комментариев и строк.

Запрос выполняется внутри транзакции, которая всегда откатывается, поэтому `DROP` и `DELETE` ничего не ломают.

## Как устроен проект

```
index.html              страница
css/, js/               интерфейс (app.js), схема БД (schema.js), движок БД (engine.js), проверка (checker.js)
vendor/marked.esm.js    разбор Markdown
data/                   pizza.sql (модель из школы), pizza_alt.sql (скрытые данные), pizza_schema.md
tasks/dayNN/exNN_name/  задания (исходники)
tasks.json              собранные задания; страница читает именно его
tools/build.mjs         собирает tasks.json из папок
tools/validate.mjs      проверяет сами задания на настоящем PostgreSQL
```

## Как добавить задание

1. Создай папку `tasks/day01/ex03_название/` с файлами: `README.md` (условие), `theory.md`, `hints.md` (каждая подсказка начинается с `## Заголовок`), `solution.sql`, `solution_commented.sql`, `meta.json`.
2. В `meta.json`: `title`, `dataset`, `ordered`, `forbidden` и `required` (списки слов), `positive` (другие верные решения, которые должны проходить) и `negative` (типичные ошибки, которые должны отклоняться), у каждого пример есть `why` и `sql`. Если названия столбцов не важны, добавь `"checkColumns": false`.
3. Запусти `node tools/build.mjs` и закоммить обновлённый `tasks.json`.
4. Проверь задания на настоящей базе (нужны `psql` и пустая база):

```
createdb trainer_test
PGDATABASE=trainer_test node tools/validate.mjs --verbose
```

Валидатор убеждается, что эталон и все `positive` проходят, а все `negative` отклоняются.

## Что проверено, а что нет

Проверено на PostgreSQL 16: все эталоны, все `positive` и `negative`, проверка и сообщения об ошибках; интерфейс в Chromium (дерево, вкладки, подсказки по одной, запуск по Ctrl+Enter, вердикты, прогресс и тема после перезагрузки).

Не проверено: загрузка самого PGlite с CDN в реальном браузере (в среде, где собирался проект, CDN и npm закрыты, поэтому в тесте движок подменялся локальным PostgreSQL). Для этого и нужен `?selftest`. Отличия PGlite от PostgreSQL 16 для этих заданий не ожидаются, но порядок сортировки строк в разных регистрах может отличаться от сервера школы.
